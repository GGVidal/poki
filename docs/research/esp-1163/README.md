# 语音桥接说话结束判定对照

## 结论

**建议暂时保留静音阈值。** 正式回放只拿到三个配对。两种判定都在地址中途切开同一句，并点了缺少门牌和楼层的选项。两组都完成的短命令和更正样本中，语义判定的首个有效动作晚了 484 和 887 毫秒。现有证据不足以确认提速。

计划中的 50 次正式回放有 6 次收到服务端音频事件。其余 44 次在送音频前失败，详见下表。背景噪声和英文有预跑结果。每个样本的五次完整配对仍待补齐。

## 对照范围

基线为 0.4.7 候选提交 `b753e543d`。候选历史包含 [GPT-Live 1.1 改动](https://github.com/JosssphZhou/poki/pull/544) 的分支头。该拉取请求在实验时仍未合并到主分支。

候选语音桥接默认协商 GPT-Live 1.1。它的 Live 会话端点未接收说话结束判定参数。桥接的 Realtime 端点已有两个选项，使用同一个 `gpt-realtime-2.1` 模型。下表适用于这个端点。[候选语音桥接](https://github.com/JosssphZhou/poki/blob/b753e543d9537babda9ac43707fda90de5aad8cf/bin/voice-bridge.mjs) [OpenAI 说话结束判定](https://developers.openai.com/api/docs/guides/realtime-vad)

| 选项 | 服务端确认的设置 |
| --- | --- |
| 静音阈值 | 静音 450 毫秒，前缀 300 毫秒，音量阈值 0.5 |
| 语义判定 | 积极程度为高，结束等待随语音变化 |

两边使用同一账号、默认推理档、近场降噪、中文转录和同一组桥接工具。计划每条录音各回放五次，按样本交替运行。每轮新建 Realtime 会话，将同一段 PCM 按 40 毫秒分帧实时送入音频缓冲区。两边都由服务端提交本轮音频，再由客户端请求回复。现有开发回放直接创建用户音频消息，会绕过说话结束判定，所以本次从桥接录音端点取音频，从 Realtime 音频缓冲入口回放。[候选语音客户端](https://github.com/JosssphZhou/poki/blob/b753e543d9537babda9ac43707fda90de5aad8cf/native/ios-app/Poki/Voice/VoiceModel.swift) [Realtime 事件](https://developers.openai.com/api/reference/resources/realtime/server-events)

工具走候选 Mac 语音桥接的 `--mac-tools` 路径和隔离的本机 Poki 服务。每次从同一台 iPhone 17 Pro、iOS 27.2 模拟器的测试页面进入。打开应用时，把明确的中英文应用名统一成该应用的标识，再由桥接实际打开。用独立的系统辅助功能查询确认前台应用。地址与联系人使用本地 Safari 页面上的虚构选项。每次回放前重置页面。脚本记录页面收到的点击请求和最后选中项。Safari 网页正文不在本机辅助功能树中，浏览器场景沿用桥接的屏幕文字识别选取按钮，模型调用读屏时会补充实际截图的识别结果。

## 录音与判定

| 样本 | 口令 | 完成条件 |
| --- | --- | --- |
| 短命令 | 打开照片 | 照片在前台 |
| 停顿地址 | 点一下页面上的和平路，停顿 1.15 秒，十七号三楼 | 页面选中和平路17号3楼 |
| 联系人更正 | 点一下页面上的林小河，停顿 1.15 秒，抱歉，改成林小雨 | 页面最终选中林小雨，同时记录曾点错对象 |
| 背景噪声 | 在合成噪声中说「打开设置」 | 设置在前台 |
| 英文短命令 | Open the Photos app. | 照片在前台 |

录音由 macOS 语音合成后保存为无损文件。停顿和噪声由脚本加入。清单给出原文、每一段语音的时点和回放字节的校验值。地址和联系人是虚构数据。[录音及回放清单](samples.json)

- 等待以标注的最后一句结束为零点。分别记录收到最终说话停止事件、首个经结果确认的正确动作发出、独立确认目标的耗时。
- 在标注结束前超过 100 毫秒就被服务端切分的事件记为提前截断。地址和更正另计停顿中的切分。动作发出早于最后一句结束时记为提前发出，模型提议、实际点击错目标和最终状态分别计数。
- 只有最终目标经独立读回且存在对应正确动作时记成功。首个有效动作的百分位数使用成功轮次，表中同时列出成功数、总轮次和时间范围。各轮的延迟、错误、取消和无动作记录保留在原始记录中。
- 用服务端回复及转录的用量和公开单价估算美元成本。缓存输入按对应单价计算。没有用量的事件单列。估算不含预跑和账户折扣。[OpenAI 公开单价](https://developers.openai.com/api/docs/pricing) [Realtime 计费事件](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime)

## 正式回放

表中的次数只含收到音频事件的轮次。斜线前后依次为静音阈值和语义判定。延迟单位为毫秒。样本量为一时，P50 和 P95 都等于单次观测值。

| 样本 | 有音频轮次 | 成功 | 提前截断轮次 | 最终停止事件等待 | 首个有效动作 P50 | 首个有效动作 P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 短命令 | 1 / 1 | 1 / 1 | 0 / 0 | 810 / 1132 | 1384 / 1868 | 1384 / 1868 |
| 停顿地址 | 1 / 1 | 0 / 0 | 1 / 1 | 816 / 1148 | 无 / 无 | 无 / 无 |
| 联系人更正 | 1 / 1 | 1 / 1 | 1 / 1 | 811 / 989 | 2501 / 3388 | 2501 / 3388 |
| 背景噪声 | 0 / 0 | 未测 | 未测 | 未测 | 未测 | 未测 |
| 英文短命令 | 0 / 0 | 未测 | 未测 | 未测 | 未测 | 未测 |

两边各成功 2 次，提前截断率都为 2/3，成功率都为 2/3。两边各有一次提前提议操作，均未在口令结束前发出实际操作。两边各点击了一次错误地址，正确动作无重复。成功轮次首个有效动作范围为 1384 至 2501 毫秒和 1868 至 3388 毫秒，P50 约为 1943 和 2628 毫秒，P95 为 2501 和 3388 毫秒。P95 在这组样本里等于最慢一次，不能估计日常使用的长尾。

### 停顿地址和联系人

### 成本、等待与故障

正式收到音频的三轮估算成本为静音阈值 0.043701 美元、语义判定 0.032598 美元，分别产生 10 和 8 个回复。已收到的标价用量齐全。次数过少，且回复数不同，无法据此判断更换判定能否省钱。成功轮次从发出动作到独立确认还需要约 3.4 至 5.3 秒，超过成功轮次在两种模式下观察到的判定等待差。回放分帧最大迟到为 58 毫秒。客户端事件只支持分段计时，服务端内部耗时没有单独观测。

50 次正式尝试中，6 次进入音频回放，36 次在建立 Realtime 会话时收到桥接 HTTP 500，8 次在模拟器打开测试页面时收到系统服务连接中断。同一建会业务请求直接返回连接重置，故障出现在桥接连接上游期间。44 次均未发送录音，保留在记录中，未计入判定成功率。模拟器服务中断后，专用实例重新启动。续跑确认正确找出了缺少完整配对的 44 个位置。前 4 次建会仍返回 HTTP 500，脚本保留记录后退出，未新增音频轮次。[补测记录](retry-attempts.jsonl)

这轮覆盖 Mac 语音桥接、真实 Realtime 服务和独立模拟器操作。录音是合成语音。地址和联系人是可观察的页面选择，适用范围限于两个测试按钮，现场麦克风、手机直连和真实通讯录不在这组测量内。

## 复跑

准备可用的 OpenAI API 凭据、Node.js 26、FFmpeg、Xcode 和一台启动的独立 iOS 27.2 模拟器。把模拟器命名为 `Poki ESP-1163 VAD`。先安装此候选的 Node 依赖，并按 [原生辅助程序构建入口](../../../bin/build-native) 准备 `build/simulator` 和 `build/ocr`。运行时用已有本机配置将凭据传给进程。脚本使用仓库中的录音，无需重新合成。

```sh
node scripts/compare-voice-turn-detection.mjs <模拟器编号> <新输出目录> 5
node scripts/summarize-voice-turn-detection.mjs <输出目录>/trials.jsonl
```

脚本在回环地址临时启动语音桥接、本机 Poki 服务和测试页面。输出目录保留逐次事件和首轮屏幕图。分开指定输出目录可保留多次实验。报告中的逐次事件可以直接汇总。公开记录以段序号代替了服务端返回的段标识，并省略了失败日志中的本地模拟器编号及端口。

```sh
node scripts/summarize-voice-turn-detection.mjs docs/research/esp-1163/trials.jsonl
```

依赖恢复后，传入上次的逐次事件文件，新输出目录只运行尚未得到两边结果的配对。若某一对只有单边结果，会重跑这对，原先的测量和错误仍留在旧目录。重复尝试产生的文件各自保留。

```sh
node scripts/compare-voice-turn-detection.mjs <模拟器编号> <新的补测目录> 5 all <上次输出目录>/trials.jsonl
```
