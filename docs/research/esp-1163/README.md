# 语音桥接说话结束判定对照

## 结论

**暂时保留静音阈值。** 50 次正式回放中，语义判定的首个有效动作中位数从 1557 毫秒增至 1769 毫秒，P95 从 6771 毫秒降至 3388 毫秒。19 个两边都成功的配对中，语义判定有 14 个更慢。两种判定都在全部五次地址样本的停顿处切开了同一句。语义判定未见稳定提速，不建议用于手机直连。

## 对照范围

基线为 0.4.7 候选提交 `b753e543d`。候选历史包含 [GPT-Live 1.1 改动](https://github.com/JosssphZhou/poki/pull/544) 的分支头。实验开始时，该拉取请求仍未合并到主分支。

候选语音桥接默认协商 GPT-Live 1.1。它的 Live 会话端点未接收说话结束判定参数。桥接的 Realtime 端点已有两个选项，使用同一个 `gpt-realtime-2.1` 模型。下表适用于这个端点。[候选语音桥接](https://github.com/JosssphZhou/poki/blob/b753e543d9537babda9ac43707fda90de5aad8cf/bin/voice-bridge.mjs) [OpenAI 说话结束判定](https://developers.openai.com/api/docs/guides/realtime-vad)

| 选项 | 服务端确认的设置 |
| --- | --- |
| 静音阈值 | 静音 450 毫秒，前缀 300 毫秒，音量阈值 0.5 |
| 语义判定 | 积极程度为高，结束等待随语音变化 |

两边使用同一账号、默认推理档、近场降噪、中文转录和同一组桥接工具。每条录音在两种判定下各回放五次，按样本交替运行。每轮新建 Realtime 会话，将同一段 PCM 按 40 毫秒分帧实时送入音频缓冲区。两边都由服务端提交本轮音频，再由客户端请求回复。现有开发回放直接创建用户音频消息，会绕过说话结束判定，所以本次从桥接录音端点取音频，从 Realtime 音频缓冲入口回放。[候选语音客户端](https://github.com/JosssphZhou/poki/blob/b753e543d9537babda9ac43707fda90de5aad8cf/native/ios-app/Poki/Voice/VoiceModel.swift) [Realtime 事件](https://developers.openai.com/api/reference/resources/realtime/server-events)

工具走候选 Mac 语音桥接的 `--mac-tools` 路径和隔离的本机 Poki 服务。每次从同一台 iPhone 17 Pro、iOS 27.2 模拟器的测试页面进入。打开应用时，把明确的中英文应用名统一成该应用的标识，再由桥接实际打开。用独立的系统辅助功能查询确认前台应用。地址与联系人使用本地 Safari 页面上的虚构选项。每次回放前重置页面。脚本记录页面收到的点击请求和最后选中项。Safari 网页正文不在本机辅助功能树中，浏览器场景沿用桥接的屏幕文字识别选取按钮，模型调用读屏时会补充实际截图的识别结果。

## 录音与判定

| 样本 | 口令 | 完成条件 |
| --- | --- | --- |
| 短命令 | 打开照片 | 照片在前台 |
| 停顿地址 | 点一下页面上的和平路，停顿 1.15 秒，十七号三楼 | 页面选中和平路17号3楼 |
| 联系人更正 | 点一下页面上的林小河，停顿 1.15 秒，抱歉，改成林小雨 | 页面最终选中林小雨，同时记录曾点错对象 |
| 背景噪声 | 在合成噪声中说「打开设置」 | 设置在前台 |
| 英文短命令 | Open the Photos app. | 照片在前台 |

录音由 macOS 语音合成后保存为无损文件。停顿和噪声由脚本加入。清单给出原文、每一段语音的时点和回放字节的校验值。地址和联系人是虚构数据。[录音及回放清单](samples.json)

- 等待以标注的最后一句结束为零点。分别记录收到最终说话停止事件、首个经结果确认的正确动作发出、独立确认目标的耗时。
- 在标注结束前超过 100 毫秒就被服务端切分的事件记为提前截断。地址和更正另计停顿中的切分。动作发出早于最后一句结束时记为提前发出，模型提议、实际点击错目标和最终状态分别计数。
- 只有最终目标经独立读回且存在对应正确动作时记成功。首个有效动作的百分位数使用成功轮次，表中同时列出成功数、总轮次和时间范围。各轮的延迟、错误、取消和无动作记录保留在原始记录中。
- 用服务端回复及转录的用量和公开单价估算美元成本。缓存输入按对应单价计算。没有用量的事件单列。估算不含预跑和账户折扣。[OpenAI 公开单价](https://developers.openai.com/api/docs/pricing) [Realtime 计费事件](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime)

## 正式回放

各样本每种判定 5 次。每格斜线前后依次为静音阈值和语义判定。各延迟单位为毫秒，首个有效动作的百分位数仅用成功轮次计算。单个样本最多有 5 次成功，其 P95 等于最慢的一次。

| 样本 | 成功次数 | 目标读回次数 | 提前截断轮次 | 最终停止等待 P50 | 首个有效动作 P50 | 首个有效动作 P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 短命令 | 5 / 5 | 5 / 5 | 0 / 0 | 810 / 911 | 1400 / 1573 | 1739 / 1868 |
| 停顿地址 | 2 / 3 | 3 / 4 | 5 / 5 | 820 / 979 | 4841.5 / 2987 | 6771 / 3524 |
| 联系人更正 | 5 / 4 | 5 / 4 | 5 / 5 | 801 / 938 | 2501 / 2937.5 | 6789 / 3388 |
| 背景噪声 | 5 / 4 | 5 / 5 | 0 / 0 | 833 / 971 | 1414 / 1744.5 | 2516 / 1884 |
| 英文短命令 | 5 / 5 | 5 / 5 | 0 / 0 | 818 / 915 | 1477 / 1540 | 1650 / 1769 |
| 总计 | 22 / 21 | 23 / 23 | 10 / 10 | 816 / 938 | 1557 / 1769 | 6771 / 3388 |

- 静音阈值与语义判定的成功率为 88% 和 84%。若仅看最终目标是否读回，两边都是 23/25。两边各有一次地址最终正确，但两次工具操作重叠，脚本无法把正确点击的时间归到该次调用，按事先约定的成功条件未计入。另有一次语义判定下的设置打开超时，最后读回设置已在前台，语音仍报未打开。
- 有 19 对在两边都成功，语义判定在其中 5 对更快、14 对更慢，配对中位差晚 84 毫秒，范围为早 3922 毫秒至晚 887 毫秒。成功轮次的原始范围为静音阈值 1315 至 6789 毫秒、语义判定 1417 至 3524 毫秒。
- 两边提前截断率均为 40%。模型分别提前提出 5 次和 2 次操作，实际在口令结束前发出 2 次和 0 次操作。记录中经工具与页面共同确认的错误点击分别为 4 次和 2 次，正确操作的重复次数均为 0。

### 英文短命令

服务端确认 10 次英文回放的转录提示都是 `zh`。两边各 5 次都保留了英文原句「Open the Photos app.」，并读回照片在前台。语音回复沿用中文界面语言。这一条英语样本未观察到中文提示造成的转录失败。由于没有英语提示对照，无法量化它在其他口令上的影响。[逐次事件与转录](trials.jsonl)

语义判定在这组录音里缩短了长尾，估算费用也较低。静音阈值的两次最慢有效动作来自地址和联系人样本，记录分别显示先点错再修正、先读屏再选中。服务端发出最终停止事件后，工具决策、文字定位和执行都计入用户等待。成功轮次中，动作发出至独立确认的中位数约为 3.10 和 2.87 秒。服务端内部耗时无法单独观测。

每种判定 25 次的音频分帧迟到 P50 分别为 2 和 1 毫秒。静音阈值的噪声第 3 轮最大迟到 505 毫秒，语义判定的全样本最大迟到为 58 毫秒。全部轮次均保留。50 次总标价估算为 0.487874 美元。

### 回放中断与恢复

首批 50 次计划中，6 次送入音频，36 次在建会时收到桥接 HTTP 500，8 次因模拟器服务断开而未进入回放。重启测试实例后的首次补测仍有 4 次建会失败。按调度要求后台等待 20 分钟后，重新启动同一独立模拟器，续跑缺失的 44 次，包含模拟器中断的 8 次。44 次均进入回放，和首批 6 次合计 50 次。故障尝试均保留，成功率以送入录音的 50 次为分母。[首批失败记录](initial-failures.jsonl) [首次补测失败记录](retry-attempts.jsonl) [早期预跑记录](pilot-noise-english.jsonl)

调研覆盖 Mac 桥接、真实 Realtime 服务与独立模拟器动作。合成录音、两个虚构选项和一个 1.15 秒停顿只能说明这些情境。现场麦克风、手机直连和真实通讯录没有进入对照。

## 复跑

准备可用的 OpenAI API 凭据、Node.js 26、FFmpeg、Xcode 和一台启动的独立 iOS 27.2 模拟器。把模拟器命名为 `Poki ESP-1163 VAD`。先安装此候选的 Node 依赖，并按 [原生辅助程序构建入口](../../../bin/build-native) 准备 `build/simulator` 和 `build/ocr`。运行时用已有本机配置将凭据传给进程。脚本使用仓库中的录音，无需重新合成。

```sh
node scripts/compare-voice-turn-detection.mjs <模拟器编号> <新输出目录> 5
node scripts/summarize-voice-turn-detection.mjs <输出目录>/trials.jsonl
```

脚本在回环地址临时启动语音桥接、本机 Poki 服务和测试页面。输出目录保留逐次事件和首轮屏幕图。分开指定输出目录可保留多次实验。报告中的逐次事件可以直接汇总。公开记录以段序号代替服务端段标识，并省略失败日志中的本地模拟器编号及端口。逐次记录的批次字段标明该轮来自最初运行还是等待后的补测。

```sh
node scripts/summarize-voice-turn-detection.mjs docs/research/esp-1163/trials.jsonl
```

依赖恢复后，传入上次的逐次事件文件，新输出目录只运行尚未得到两边结果的配对。若某一对只有单边结果，会重跑这对，原先的测量和错误仍留在旧目录。重复尝试产生的文件各自保留。

```sh
node scripts/compare-voice-turn-detection.mjs <模拟器编号> <新的补测目录> 5 all <上次输出目录>/trials.jsonl
```
